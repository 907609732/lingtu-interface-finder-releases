# 文件夹包同步指南

**简体中文** | [English](folder-package-sync.en.md) · [返回首页](../README.md)

更新于 2026-11-12。本指南描述正在开发的文件夹包模式。公开的 `extension-v0.7.4` 和历史 0.5.x 包尚未包含此功能，请以未来对应发行说明确认可用版本。

## 两个目录，各管什么

| 位置            | 保存内容                                     | 如何变化                                 |
| --------------- | -------------------------------------------- | ---------------------------------------- |
| ArtHub 同步目录 | 项目清单、文件夹 ZIP、提交 JSON、检查点      | 人工提交后发布，ArtHub 负责传输          |
| 本机数据目录    | 解包资料、未提交草稿、已接收状态、索引和缓存 | 日常编辑自动保存，接收更新后切换完整数据 |

两者必须分开放置，本机数据目录放在 ArtHub 同步范围之外。软件不调用 ArtHub 上传 API，也不把“写入目录成功”当成“云端同步完成”。

## 首次接入

1. 等 ArtHub 把项目文件同步到当前电脑的目录。
2. 首次打开软件时选择项目同步目录；之后可从“设置 → ArtHub 文件夹包同步 → 选择 ArtHub 同步目录”切换。
3. 软件读取清单和日志，校验完整 ZIP 后解压到本机数据目录。日志先到、包未到齐或包损坏时，保留上次完整版本并等待。
4. 在设置中查看“同步目录”和“本机数据”位置。已有本机缓存时可先打开资料，后台检查新提交；同步目录离线时仍可使用已接收资料。
5. 如需 AI 搜图，每台电脑分别下载或导入模型，并在本机运行索引。模型、图片索引、查询数据库及显卡缓存不放进共享资料包。

## 编辑与人工提交

1. 上传素材、编辑名称／字段或恢复历史版本，先保存为本机草稿。
2. 点击顶部“提交更新”，查看待提交文件夹及每个文件夹的变更。
3. 勾选要发布的文件夹并填写提交说明。移动资料、调整父子目录等关联修改会一并选择。
4. 点击面板中的“提交更新”。软件固定本次快照，完成 ZIP 校验，再将包和最后的提交日志发布到同步目录。
5. 确认界面显示发布完成、待提交数量更新。之后由 ArtHub 继续传输；云端进度以 ArtHub 自身显示为准。

提交期间继续编辑产生的后续改动仍属于待提交草稿。发布中断时可继续发布或放弃本次快照，放弃快照会保留本机草稿。

## 为什么按文件夹打包

每个文件夹只包含自己的直接资料、相关历史修订和原件；子文件夹独立打包，父包保存子目录关系。项目公共资料另有一个包。包以内容哈希命名，不覆盖已有版本。

一次小修改通常只新增涉及文件夹的包及一个 JSON 日志；不是每条数据一个包，也不会因为修改子目录而把整个上级系统重新打包。跨目录移动可能涉及多个关联包。

此粒度有固定开销：文件夹数量很大、每个文件夹只有少量资料时，总文件数不一定下降。历史包随提交增长，应按团队需要定期整理。

## 另一端如何更新

另一端发现新日志后，等待所有引用的包和前置提交到齐，校验哈希、解压到临时工作区，完整成功后切换本机数据。通常自动检测，也可点击“检查接收更新”。

本机未提交的修改会保留。多人同时修改同一资料时，软件保留冲突分支，需要在历史／冲突入口处理后再提交，不采用最后写入者静默覆盖。当前机制不提供跨电脑的原子编辑锁。

## 已验证的操作示例

| 步骤     | 第一端 A                                | 第二端 B     | 同步文件变化                              |
| -------- | --------------------------------------- | ------------ | ----------------------------------------- |
| 初始     | 任务追踪主界面.png                      | 同名         | 无                                        |
| 保存草稿 | 改为任务追踪主界面_人工提交演示.png     | 仍为旧名     | 0 个新增文件，原文件哈希不变              |
| 人工提交 | 选择“任务追踪 / 01 总览与导航 / 主界面” | 尚未接收     | 新增 ZIP 47,883 字节＋JSON 812 字节       |
| 接收更新 | 显示新名                                | 自动显示新名 | 两端修订和原图哈希一致，保留 2 个资料修订 |

此次演示使用两个独立源码运行时、独立本机数据目录及同步目录，以本地复制模拟 ArtHub 传输。同步目录由 783 个文件增至 785 个；只新增了一个文件夹包和一个提交日志，其他包未重打。真实 ArtHub 云端、占位下载和两台物理电脑仍待验收。

## 从旧资料库迁移

1. 先保留旧资料库及备份，确认参与客户端都支持文件夹包协议；迁移时停止编辑并等待旧目录同步完整。
2. 打开旧库，在设置中选择“将当前资料库迁移为文件夹包”。
3. 选择旧库之外的一个新空目录作为 ArtHub 同步目录。软件生成迁移副本并校验；原库保留。
4. 用新客户端检查目录、资料、图片和历史，再让其他电脑选择同一个新项目。旧客户端不能直接使用新项目。
5. 回退时可重新打开保留的旧库；迁移后的新增修改需另外导出保留，不会自动回写旧库。

已有 AI 搜图缓存属于本机数据。切换到新项目后可能需要重新生成索引，不影响原图与资料。

## 历史、检查点与文件数

在设置中查看提交历史，恢复旧资料会生成本机草稿，需要人工提交才能发布给其他电脑。

“整理同步历史”先创建检查点，再允许人工清理已覆盖的旧包和日志；清理前重新校验同步目录中保留的检查点及其包。**确认团队电脑已接收检查点、ArtHub 已完成传输并保留备份后再整理。** 软件无法替 ArtHub 确认云端完成状态。

长期离线、缺少前置提交的机器会先等待；完整的迟到提交可人工导入为草稿，再检查和提交。检查点清理不等于全局分布式锁。

## 当前边界

- 包内解压数据不超过 3 GB、30,000 个条目、32 MiB 元数据；提交日志不超过 1 MiB。日志大小随提交范围增长，不保证每次都只有几 KB。
- 首次导入大库仍可能耗时；本地演示不代表千图索引速度、低配电脑性能或实际网络传输耗时。
- 已修复 Windows 深层本机缓存路径导致的图片“等待预览”，无需搬动原图或重新上传。
- 本模式不共享 AI 索引、不并发打开共享 SQLite／LanceDB，也不提供 ArtHub 云端状态 API。
