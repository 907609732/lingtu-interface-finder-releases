# ArtHub 普通文件夹同步指南

**简体中文** | [English](folder-package-sync.en.md) · [返回首页](../README.md)

更新于 2026-11-18。0.7.5 的同步方式是：资料库就是一个普通文件夹，原图、不可变修订和目录记录直接保存在文件夹中，由 ArtHub 负责同步。此功能已包含在 0.7.5；历史 `extension-v0.7.4` 和 0.5.x 安装包不包含。

> 历史说明：2026-11-12 验证过“每个文件夹一个包 + 人工提交”的开发版。该日常流程已停用，只保留旧 format 3 项目的只读迁移兼容；本文档不再是打包发布指南。

## 一个普通文件夹，各管什么

| 位置 | 保存内容 | 如何变化 |
| --- | --- | --- |
| ArtHub 同步文件夹 | `library.json`、`revisions/`、`assets/`、`media/`、`catalog/revisions/` | 保存后立即写入，ArtHub 自行传输 |
| 每台电脑的本机缓存 | SQLite、query-cache、缩略图/预览、特征与 AI 索引、任务、回收站 | 只留在本机，不进入共享文件夹 |

两者必须分开放置。应用不调用 ArtHub 上传 API，也不会把“写入目录成功”显示成“云端同步完成”；云端进度以 ArtHub 自身显示为准。

## 首次接入

1. 等 ArtHub 把资料库文件夹同步到当前电脑。
2. 在首页选择“打开资料库文件夹”，或在设置中选择同一个普通目录。
3. 软件直接读取 `library.json`、不可变修订和原件；不会创建打包项目，也不会自动解包。
4. 如需 AI 搜图，每台电脑分别下载或导入模型。SQLite、向量索引、预览和回收站由本机维护。
5. 文件夹暂时离线时，已经打开的页面和本机缓存不会被删除；重新连接后再由 ArtHub 同步。

新建资料库时选择一个空文件夹即可。软件会写入普通资料库结构和 `.gitignore`，不生成 `packages/`、`commits/` 或本机 `state.json`。

## 编辑与同步

1. 上传素材、编辑名称/字段或恢复历史版本，保存后直接写入普通文件夹。
2. 不可变修订继续使用父修订关系；两人修改同一资料时保留冲突分支，不静默选胜者。
3. ArtHub 负责把新增修订和原件传到其他电脑。另一台电脑打开同一文件夹即可读取。
4. 没有“提交更新”按钮，没有打包、人工发布、自动解包或检查点清理的日常入口。
5. 本机缓存与共享目录分离，避免把 SQLite、LanceDB、预览或显卡缓存写进 ArtHub 文件夹。

## 从旧文件夹包迁移

旧 `format: 3 / folder-packages` 项目不能在当前版本中继续编辑。首次打开只会提示只读迁移，不会自动创建空资料库。

1. 在设置或首页选择“迁移旧文件夹包到普通资料库”。
2. 选择旧同步目录。软件优先读取设置中记录的本机工作区；找不到时会明确提示只能迁移旧目录中已完整提交的数据。
3. 选择一个空目标文件夹。非空目录会被拒绝，原目录不会被覆盖。
4. 迁移器把最新本机 generation 复制到旁路普通目录，保留本机未提交修订、冲突、prepared/outgoing 快照引用的修订与原件，并在可用时先只读接收远端独有提交。
5. 复制完成后逐个校验文件 SHA-256、修订引用、原件和回收站；目标校验通过前不切换。迁移中断、失败或检测到源项目并发变化时，目标不会切换，可修正原因后重试。
6. 本机回收站按原 library ID 和记录路径复制到新缓存目录，迁移后仍可从回收站恢复。
7. 旧目录、包、`state.json`、`outgoing/`、`archives/` 和本机回收站都不删除。迁移日志写在本机缓存的 `migrations/` 下，记录源、目标、计数、树哈希和回退说明。

离线迁移只使用本机最新 generation，并在日志中标注“未应用的远端独有提交仍在旧目录”。恢复 ArtHub 连接后应再次核对；迁移器不会猜测补齐缺少的原件或损坏的包。

## 当前边界

- 迁移不会把 AI 模型、查询数据库、预览或特征缓存复制到共享目录。
- 旧包中不完整、损坏或缺少原件的提交不会被自动修复；迁移器会停止并保留旧数据。
- 真实 ArtHub 双机传输、占位文件、网络中断和云端完成状态仍以实际环境验收为准。
- 旧客户端不能继续编辑新的普通资料库格式；回退前应保留迁移后新增的修改。
